# Use creation-time compatibility classes for Native replay

Native replay prefers equality of OpenAI Codex's opaque Compaction compatibility class for Eligible producers and targets, allowing compatible history to cross model IDs, Pi providers, and the two Eligible Responses API types; if either class is unavailable, it falls back to the exact Model key, and legacy checkpoints retain exact-key semantics. Because Pi `0.84.2` exposes neither the provider-resolved class nor per-turn extension metadata, the extension accepts a source-backed local Codex catalog and branch-local request-time Compatibility decision records as deliberate maintenance debt, with release updates expected mainly when OpenAI introduces models rather than as a continuously refreshed compatibility service; persisting every checkpoint's creation-time class prevents later catalog revisions from reinterpreting history. This supersedes ADR-0004's exact-Model-key compatibility conclusion but retains its separation of endpoint, account, authentication, and header routing data from persisted identity; target-service acceptance remains a runtime assumption.
