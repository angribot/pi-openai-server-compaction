# Select models by API contract and known compatibility class

Remote compaction eligibility requires a known Compaction compatibility class and either exact `openai-responses` for any provider, or Pi's built-in `openai-codex` provider with exact `openai-codex-responses`; the latter is provider-scoped because Pi's Codex API is the ChatGPT OAuth protocol rather than a third-party-compatible Responses API. API-only selection was too broad, so the release-managed Codex catalog now also bounds attempts to models with a resolved class, trading coverage of uncatalogued models for a narrower opt-in boundary without remote discovery or configuration. Models without a resolved class remain on Pi's default compaction path; eligibility permits only an attempt, while endpoint capability remains runtime-discovered and Native replay compatibility remains a separate decision.
